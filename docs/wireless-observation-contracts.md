# Passive wireless observations

These three feature contracts use the existing architecture-v6 typed collections, exact local selectors, iwinfo probe, dispatcher and bounded backends. No architecture boundary, dependency, permission engine or probe family changes were needed. The contract was specified before implementation; the implementation now passes the native Windows GNU and Linux-on-WSL gates with ten additional feature/MCP regressions. This is synthetic acceptance, not radio/device acceptance.

| Operation | Fixed target request | Result |
| --- | --- | --- |
| wireless_stations | iwinfo.assoclist with device only | Bounded station records from results |
| wireless_station_status | The same full assoclist; mac selects locally | One exactly matching station record |
| wireless_countries | iwinfo.countrylist with device only | Bounded driver-reported country records |

Every operation requires Wireless.Read and no execution grant. The operator explicitly choosing Wireless.Read now permits station MAC identities and radio-link metadata, not only radio statistics. Deny both station operations to withhold client identities. Default policy still denies every operation. No active scan, disconnect, country setting, hostapd mutation or UCI output is introduced.

`device` follows the existing required String argument contract: at most 1,024 UTF-8 bytes, no NUL, literal transmission, no command interpretation. `mac` is required only for exact selection, nonempty and at most 17 bytes. Selection is case-sensitive and literal; use the returned identity. It is never sent to rpcd's optional `mac` filter. Missing/invalid selectors fail before I/O; absent matches return `selection_not_observed`, not proof of disconnection. Duplicate identities and malformed unselected records fail the entire call.

Station identity is required `mac` text (at most 17 bytes), with required `signal_dbm` and `noise_dbm` signed integers in -128..127. Optional fields are signal_average_dbm; nonnegative signed-32-bit inactive_ms, connected_seconds, estimated_throughput_kbps, rx/tx_rate_kbps and rx/tx_bandwidth_mhz; Boolean authorized, authenticated, wme, mfp; and rx_bytes, tx_bytes, rx_dropped as nonnegative integer inputs returned as decimal strings. Source pointers are fixed. Null, coercion or out-of-range values fail. Negative values from a wrapped upstream counter are rejected, never reinterpreted or reported as accurate traffic totals. Missing optional counters remain omitted.

Country identity is required `iso3166` text (nonempty, at most two bytes), with required `code` (at most four bytes) and `country` (at most 256 bytes); `active` is optional Boolean. This is observed driver metadata, not a legal compliance verdict or authority to set a country. Unknown fields, SSIDs, BSSIDs, keys, configuration, arbitrary nested data and station mesh details are not returned. The station MAC is an intentional disclosed identity, not a failure of redaction.

RX/TX use the target driver's viewpoint. Numeric zero and false are reported values and may originate in upstream defaults when a particular measurement or flag is unavailable; they are not inferred health, authentication or link-quality verdicts. This bounded-text profile checks identity presence/uniqueness/size, not MAC-address or ISO-code syntax.

Station calls scan at most 128 records, including exact selection; country calls at most 256. Existing aggregate 256-item, normalized 64-KiB and MCP result 256-KiB limits still apply, with no truncation. Source order is preserved. A valid empty `results` array is an empty RPC observation only: rpcd may return it when a driver callback fails. It does not prove no clients, no countries, or healthy hardware.

Source review: the pinned [rpcd iwinfo implementation](https://github.com/openwrt/rpcd/blob/e37ed9d814699098eb7e26c8b33c054840782dfb/iwinfo.c) declares device/mac inputs, emits association metrics in assoclist and country metadata in countrylist. Its callbacks can yield empty results without a distinct error. The [libubox JSON formatter](https://github.com/openwrt/libubox/blob/e7608b69283d919d031d13cc8e21692503f5dbea/blobmsg_json.c) formats integer blob values as signed JSON numbers, so these contracts do not repair wrapped counters. The [iwinfo field types](https://github.com/openwrt/iwinfo/blob/66bdd1a071895d91babc9b9228bb84626bbce226/include/iwinfo.h) bound signal/noise to signed eight-bit values; [nl80211 units](https://github.com/torvalds/linux/blob/v6.12/include/uapi/linux/nl80211.h) define expected throughput in kbps. Version strings alone remain insufficient; same-backend input-signature and response checks are mandatory. The two library revisions are source-review references, not a claim that BPI-R4 runs those exact library builds.

Required synthetic acceptance: exact catalog/response-ID coverage; category and denylist enforcement; literal device and local-only selector action; missing/foreign capability refusal; strict types/presence/ranges; duplicate and unselected-row rejection; decimal precision above 2^53; empty observations; exact/over row limits; malformed/hidden tool zero-I/O behavior; MCP text/structured equality; and payload-free audit completion. Real radios, driver correctness and regulatory behavior require separate acceptance.
