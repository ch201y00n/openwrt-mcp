# ADR 0007: Bounded, paged package observations

Status: accepted design checkpoint. Commit and validate this architecture and its negative harness tests before production implementation. This is not package mutation or device acceptance.

## Scope and admission

Add `packages_apk_installed`, a Packages.Read operation. It captures the installed-package view reported by a reviewed APK query, validates the entire response, and serves immutable pages. This is **not an atomic whole-device inventory**, an assertion that APK is the only manager, or a transaction baseline. The response always declares `scope=apk_query_installed_visible`, `consistency=non_atomic_observation`, and `whole_device_complete=false`. Other managers, configured destinations and unreadable layers remain outside that claim. No manager precedence, automatic fallback, download or repository refresh is permitted.

The closed source recipe first observes the exact APK 3.0.5 version banner on the same backend, then executes the fixed installed query successfully and validates its complete response. Version alone never establishes compatibility. Unknown versions and malformed/nonzero results fail closed; later versions require reviewed recipes and tests, not a permissive version range. This accommodates variation explicitly without assuming one OpenWrt release implies an API. A compromised target executable can lie; pinned SSH authenticates the endpoint, not its software integrity.

Both commands use `/usr/bin/env -i`, fixed PATH and LANG=C, APK_CONFIG=/dev/null, `/usr/bin/apk`, and --no-network --no-cache --no-logfile. Query arguments are `query --from installed --installed --all-matches --format json --fields name,version,arch,layer *`, each a literal argv element, with no shell expansion. No client-selected executable, environment, path, manager, pattern or parser profile. `--version` exits before database opening. The query uses read-only database flags. The cache and logfile flags exclude persistent initialization writes; no --root/usermode/create/write option is allowed. Normal read access and kernel metadata effects are not a promise of a side-effect-free OS.

Source review: [APK option/configuration handling](https://github.com/alpinelinux/apk-tools/blob/v3.0.5/src/apk.c), [query](https://github.com/alpinelinux/apk-tools/blob/v3.0.5/src/query.c), [context](https://github.com/alpinelinux/apk-tools/blob/v3.0.5/src/context.c), [database](https://github.com/alpinelinux/apk-tools/blob/v3.0.5/src/database.c). APK_CONFIG points at an existing empty device to avoid configuration fallback. Query selects installed packages with exact names, versions, architectures and layer; omitted numeric layer means root zero in this specific serializer. Database opening attempts root and uvol, but may silently skip non-root read failures. No read lock or cross-layer atomicity is established. Therefore even a successful empty result cannot prove no packages or no hidden layer.

## Ownership and lifecycle

- `core::packages` owns exact bounded records, a privately constructed validated observation, cursor syntax and page serialization. It has no I/O, clocks, random source, async or backend dependencies.
- Features owns the closed action `ApkInstalledPage`, matching `ApkInstalledQuery` capability metadata, response contract and the optional cursor parameter. The action cannot carry CLI options. Generic Process remains unverified and blocked. The prepared invocation refuses ordinary projection of this workflow; ordinary action compilation also rejects it.
- `runtime::packages` owns the use case and private snapshot state. Dispatcher performs its normal policy, argument, concurrency, Start/Finish audit and deadline checks on every page. Initial capture uses `Backend::capture_apk_installed`, default unsupported, on the same immutable backend; this is a purpose-specific port, not generic execute bypass. No cursor reaches a backend.
- `device-codec::packages` owns only the fixed commands, version-banner validation and strict supplied-byte parser. Existing bounded process/SSH runners perform I/O. Both commands share one capture deadline; transport completion and exit success precede parsing.
- `runtime::packages::SnapshotTokens` is a small injected async nonce port. `adapters::tokens` supplies 128-bit OS randomness through getrandom 0.4.3; server composition wires it. Use a blocking worker with one adapter-owned permit held by the worker even after caller cancellation, so a blocked OS entropy call cannot block the executor or cause unbounded workers. Runtime does not import entropy or native I/O. Missing/failed entropy fails closed. This is the only added dependency edge.
- MCP continues routing all management calls through Dispatcher and bounded tool-result serialization; it does not implement paging or import snapshot state. Listing remains offline.

There is one snapshot slot and one non-waiting capture/page lock per Dispatcher, shared by all aliases of this closed workflow. A cursor is an untrusted, non-secret continuation, never a permission token. Each new capture clears old state **before** entropy or device I/O. Cancellation, failure, expiry, epoch change or completion-audit failure cannot restore it. A capture is admitted only with a nonzero random nonce and a current backend epoch; an initial lazy SSH connection may establish its epoch during capture, but an existing epoch cannot change. Compare again before returning every page. Another simultaneous capture/page returns Busy, not a queued recapture.

Store only validated records, nonce, operation name, backend epoch and monotonic capture-start time. TTL is 120 seconds from capture start, never renewed by paging. A cursor encodes the 128-bit nonce and an aligned decimal offset. Validate canonical syntax before admission; reject wrong nonce, operation, offset, expiry or epoch without backend I/O or recapture. Exact replay gives the same data page while the snapshot is valid. Separate Dispatcher instances/principals cannot share snapshots; random nonces also prevent accidental continuation across restarts. Backend reconnection requires a new epoch under the existing contract. External package writers do not update this observation; start a new capture explicitly. No persistence, background task or poller is introduced.

The initial result and continuations have fixed source/scope/consistency metadata, captured record count, offset, items and optional next_cursor. `operation_capability` for this family returns `unknown/capture_required`, scope `closed_query_response`, without capturing packages or fabricating an ubus signature. The normal audited status path still applies. It does not predict query success. Existing ubus status semantics are unchanged.

## Hard bounds and failures

Use min(operator max_output_bytes, 4 MiB) for each source command; the existing default remains 64 KiB. Version output is additionally limited to 256 bytes. The strict v6 duplicate-rejecting JSON decoder retains its existing depth/node limits. Validate at most 4,096 records, at most 2 MiB retained UTF-8 field bytes, name/version at most 256 bytes each and architecture at most 64 bytes, all nonempty and without control characters. Layer is only 0 or 1. Reject unknown response fields, duplicate identities `(layer,name)`, nulls, wrong types, malformed late rows and overflow before publishing any page. Preserve ABI suffixes; no truncation or name normalization.

Sort once by `(layer,name)` for deterministic pages. Pages contain at most 64 records, further narrowed by the existing 64-KiB normalized JSON limit; use a fixed conservative 16-record page so worst-case escaped fields and envelope fit. The contract's actual page size is therefore **16**, not a dynamic or client-selected value. Validate serialization before Finish audit. The whole MCP result remains limited to 256 KiB including both copies. Bounded raw decoding/temporary structures and index overhead are separate from the retained-field cap; no claim of a 2-MiB total RSS ceiling. All failures use safe fixed codes and never log arguments, cursors, raw databases or package output.

## Harness and acceptance

Version 7 adds a machine-checked package contract, exact owners, recipe profile, bounds, permission/admission/cache semantics, entropy edge, and five mandatory portable suites: core records/pages, codec recipe/response, runtime lifecycle, feature metadata and MCP behavior. Negative tests reject removed/altered fields, wrong bounds/owners/recipes, missing or skipped suites and missing native CI commands. Existing layering, evolution, projections and unverified Process checks remain active. Declaration scaffolds at the architecture checkpoint are not behavioral implementation.

Behavior must cover complete 281+ row enumeration, late malformed data, duplicates, empty/oversized responses, exact field preservation, all bounds, replay/foreign/expired cursors, concurrent admission, cancellation, epoch changes, failed refresh, failed audit/entropy, zero-I/O denied/invalid calls, no recapture on continuation and protocol bounds. Synthetic tests are distinct from emulator and BPI acceptance. APK query support does not implement opkg, package installation/removal, firmware or rollback; those remain explicitly tracked.
