# ADR 0008: Native Windows protected config and secret reads

Status: accepted architecture checkpoint; validate and commit declarations/harness before behavior. This does not claim implemented Windows protection or Vault acceptance.

## Scope and threat boundary

Implement the existing host-platform config-integrity and secret-confidentiality/integrity read ports on a closed local NTFS profile. Key-sources continues to select custody/container and crypto-age continues to accept supplied streams. No raw-file MCP tool, environment fallback, automatic ACL repair, privilege enablement, impersonation, Vault unlocking, private-log write, or router mutation is added. PersonalVault remains UnsupportedProtection even if an ordinary restricted file can be read. A hydrated OneDrive file is not proof of Vault membership/lock protection.

Trust the process user's SID, LocalSystem and Builtin Administrators, including their ability to alter this process. For the volume root only, also accept the fixed TrustedInstaller service SID as owner/trustee. This is not protection against the same user, administrator, compromised kernel, filesystem driver or device. Reject thread impersonation rather than reason about a different effective principal. Do not query accounts over the network or trust arbitrary token groups.

## Native read profile

Separate availability declarations: `native_file_protection_supported()` describes protected config/secret reading, while new `private_log_supported()` describes append/rotation. AuditConfig must use the latter and reject Windows file logging during offline validation. Enabling protected reads must not advertise an unimplemented write facility. Linux retains both, Windows gains only reads after acceptance, and unsupported hosts retain neither.

Accept only explicitly supplied absolute DOS drive paths, at most 4096 UTF-16 units and 128 components. Reject UNC/device/verbatim paths, alternate streams, relative drive/root paths, dot traversal, repeated/trailing separators, wildcards, NUL/control characters, invalid Unicode, reserved DOS device names and trailing dot/space components. Configuration paths in this profile must also be absolute; portable callers cannot assume every optional native profile supports relative paths. No canonicalize/short-name/environment expansion. Reject short-name aliases by comparing each opened component's final name with the requested name (case-insensitive ASCII only for ASCII casing, exact Unicode otherwise); unknown/ambiguous results fail closed.

Open the drive root once and establish a local volume-GUID root and NTFS with persistent ACL support from that handle. Reject redirected/substituted roots, unsupported/network filesystems and unknown volume metadata. Traverse one component at a time with NtCreateFile RootDirectory referring to the held parent, FILE_OPEN only, FILE_OPEN_REPARSE_POINT, explicit directory/non-directory and synchronous options. Each open omits delete sharing; the leaf also omits write sharing. Keep all ancestors until completion. Inspect every handle for disk type, expected directory state, no reparse/offline/recall flags or delete pending; the leaf must have exactly one link and bounded nonnegative size. Read from the validated owned leaf handle, never reopen by path. Deny conflicting writers/deleters rather than wait or retry. No backup-intent flag or write access.

Read owner and DACL from each handle into a bounded self-relative descriptor, at most 65536 bytes. Process token metadata is bounded to 4096 bytes. Validate structure offsets/lengths/SIDs/ACL/ACE bounds in safe Rust; absent/null DACL, missing/untrusted owner, unknown effective ACE kinds and malformed data fail closed. Standard allow and deny ACEs are the only accepted kinds; an inherit-only ACE is parsed but does not grant access on this object. Conservatively union allow grants, ignoring deny reductions: a deny cannot rescue an otherwise unsafe allow. Expand generic rights, reject unknown rights, and reject dangerous grants to every non-trusted SID, without guessing group membership. Config allows others to read; secret allows only metadata read/control/synchronize, never file data, EA data or execute. Directories allow others read/list/traverse/control/synchronize but no writes/deletion/ACL changes. At the volume root only, allow add-subdirectory (not delete-child or modification of existing entries), to accommodate the standard system-volume root; created descendants must independently pass owner/DACL checks. Every actual inherited ACE is checked as effective. Strict rejection of custom/shared ancestor ACLs is intentional.

After a bounded max+1 read, recheck leaf metadata/security and length before releasing bytes. Secret buffers are zeroizing on all error paths. Config maximum remains 1 MiB and secret maximum 16 MiB, with smaller caller limits preserved. Shared-read handles prevent ordinary concurrent writers/deleters but do not promise a kernel-enforced immutable snapshot against trusted administrators or existing writable mappings. Fixed HostError codes never include paths, descriptors, keys or upstream diagnostics. Native reads can block in the kernel; existing caller-owned bounded workers remain necessary, not a hard-real-time claim.

## Ownership and audited unsafe bridge

Keep `windows.rs` a safe façade. `windows/policy.rs` owns safe lexical and supplied-security-byte validation. `windows/native.rs` alone owns Windows SDK calls and handles; it exposes only a purpose-specific protected-read function to its parent and no handles, raw pointers, unsafe public functions or SDK namespace. Use windows-sys exactly 0.61.2, Windows-target-only, with the reviewed Foundation/Security/FileSystem/Threading/IO plus Wdk Foundation/FileSystem feature groups. No manual extern declarations, assembly, unsafe traits/impls/functions or subprocesses. OwnedHandle/File RAII closes each successfully created handle exactly once; all unsafe blocks explain pointer initialization, alignment, lifetime, output bounds and ownership. Review the SDK declarations as part of implementation, not just successful compilation.

All workspace crates retain forbid(unsafe_code) except host-platform, whose manifest sets deny(unsafe_code); the exact native file may locally allow unsafe expressions. The scanner checks all cfg branches, rejects this allowance elsewhere, and rejects SDK access outside that file even through Cargo/Rust aliases. Existing unsafe-item/FFI/macro rules remain. Contract fields, exact source owners, Windows dependency target/version/features and native suite cannot be weakened without architecture evolution. A static scanner is not a proof of soundness or every behavior of an approved dependency; review and negative tests remain essential.

## Acceptance and exclusions

Require native Windows synthetic tests for private file success/config-vs-secret distinction, every supported ACL case and malformed descriptor bounds, untrusted owner/write/read/inherited grants, null DACL, unknown ACE, insecure ancestor, short alias/ADS/path rejection, hardlink and junction/reparse rejection, size limits and conflicting handles. Tests cannot skip native failures. Use an atomic private fixture directory below a trusted non-synced parent; never repair broad/user folders. Linux/portable gates must continue passing; neither WSL nor a Linux zero-test Windows suite establishes Windows acceptance. Native MSVC and macOS acceptance remain separate from Windows GNU evidence.

Ordinary protected-file reading also permits existing bounded ZIP entry selection through key-sources, subject to the same container-file protection. It does not prove archive authenticity beyond custody or allow unsupported ZIP formats. Private logs, system logs, Vault trust/lock handling, macOS protection, UNC/ReFS/FAT/cloud placeholders, and remote/mapped-volume profiles remain unimplemented. New requirements must extend this design, not bypass its rejection with generic filesystem calls.
