# Additional base-service UCI observations (v13)

This is the implementation contract for eighteen additional parameterless reads. At the architecture-only checkpoint these tools are **not implemented**. All use the common [UCI section envelope and limits](uci-observations.md), fixed config/type/get, exact category Read, existing same-target capability checks and no execute grant. New response IDs are <tool>.v1. No existing response changes.

All fields below are optional and selected by unchanged option name. Parentheses specify UTF-8 bytes per text. Scalar means exact JSON string only; TextOption means the fixed kind/values wrapper preserving the source string or list. No parsing, defaults, splitting, joining, normalization or action is performed. Numerical-looking strings remain strings. Each option list has at most 128 values under the unchanged shared 256-item and 64-KiB output budget.

## Source and compatibility scope

The reference rpcd serializer, rather than the downstream daemon, supplies these strings/lists and section metadata. Reads do not run service validation, compile nftables, resolve names, inspect paths, start NTP/DHCP or apply a configuration. Missing selected fields do not inherit daemon defaults. Disabled or unusable sections may still be observed. Actual input signatures and output shape gate each call; a matching OpenWrt version alone never enables it.

- Network section consumers and option names: reference [netifd config.c](https://github.com/openwrt/netifd/blob/cbb83a1857407a28a63dc09412a1f209195914ef/config.c), [device.c](https://github.com/openwrt/netifd/blob/cbb83a1857407a28a63dc09412a1f209195914ef/device.c), [bridge.c](https://github.com/openwrt/netifd/blob/cbb83a1857407a28a63dc09412a1f209195914ef/bridge.c), [vlandev.c](https://github.com/openwrt/netifd/blob/cbb83a1857407a28a63dc09412a1f209195914ef/vlandev.c), [route attributes](https://github.com/openwrt/netifd/blob/cbb83a1857407a28a63dc09412a1f209195914ef/interface-ip.c) and [policy rules](https://github.com/openwrt/netifd/blob/cbb83a1857407a28a63dc09412a1f209195914ef/iprule.c). Device subtypes and runtime-created objects remain broader than this projection.
- Firewall section consumers: reference [firewall4 b6e51575](https://github.com/openwrt/firewall4/blob/b6e51575/root/usr/share/ucode/fw4.uc), parse_zone/forwarding/rule/redirect/nat. The tool does not emulate its normalization, rule generation or runtime/automatic includes. Legacy extra/extra_src/extra_dest and free-form scripts are excluded.
- DHCP sections: OpenWrt 25.12.5 [dnsmasq init](https://github.com/openwrt/openwrt/blob/v25.12.5/package/network/services/dnsmasq/files/dnsmasq.init), host/pool/domain/CNAME consumers. These are UCI observations, not proof of dnsmasq/odhcpd interpretation or complete RA/reservation support. Raw options, dhcp_option, extraconftext and script content remain excluded.
- Time service: 25.12.5 [sysntpd](https://github.com/openwrt/openwrt/blob/v25.12.5/package/utils/busybox/files/sysntpd). The service selects named ntp, while this type-filtered observation may include other timeserver sections; no enabled/effective server inference.
- Storage: 25.12.5 [fstools package pin](https://github.com/openwrt/openwrt/blob/v25.12.5/package/system/fstools/Makefile) and [global/swap options](https://github.com/openwrt/fstools/blob/16718b6e3c0fc7db7be6ae5848db0eae88ac8a8b/block.c). This source provenance is not a newly observed BPI-R4 fstools version. No mount options, filesystem contents, check, swap activation or extroot mutation.

## Security and evidence

Category Read discloses selected topology, policy, addresses, client MAC/DUID/hostnames, domain associations and disk identifiers. Use exact operation denials for narrower access. TextOption bounds the entire original string, including whitespace-separated forms; allowed text is not guaranteed to be free of target-supplied secrets. Section-map identity and package index are observations, not durable handles or application order.

These partial views cannot certify protected lan3 or indirect IPTV dependencies for writes. No backup, mutation, rollback, complete kernel/network inventory or application outcome is implied. Synthetic host, emulator and separately authorized physical-target evidence must name the actual operation and shape; empty collections are not populated acceptance.
